# 현재 제품 흐름 녹화

저장소 루트에서 `bash scripts/demo/record.sh`를 실행합니다. `.env`의 실제 Jev 연결 설정을 읽고 새 tenant, API **10291**, Vite **7591**, tenant 제한 worker를 사용합니다. 이미 해당 포트가 사용 중이면 중단하며, 종료 시 직접 시작한 프로세스만 정리합니다. 공유 OrbStack Neo4j·Redis를 중단하지 않습니다.

`artifacts/demo/<UTC 타임스탬프>/`에 다음 파일이 생깁니다.

- `walkthrough.mp4`: 1440×900, 30 fps H.264, 한국어 자막이 포함된 연속 화면 녹화
- `scene-*.png`: 15개 장면 및 인사·타이핑·잠정·취소·경로 글로우 등 중간 상태
- `chapters.md`: 실제 녹화 경과 시간 기준 챕터
- `manifest.json`, `README.md`: LIVE 요청 ID, 표시 시간, 장면 실패, 브라우저 콘솔 오류
- `raw/`: 원본 영상, 서버 로그, 녹화 전용 데이터 (git 제외)

로그인 → 인사·예시·전송 → 잠정·최종·상세 → 취소·재분석 → 대화 목록 → 수정 승인 → 업무 전이 → 실행 관찰 → 판단 맵·버전 → 규칙 학습 → 평가 칩·Enter·J → 모니터링 → 정책 폼 → 다크 모드 → 마무리 순서입니다. `reducedMotion: no-preference`로 실제 애니메이션을 녹화합니다.

학습 장면 준비를 위해 녹화 전에 가상 요청 3건을 실제 LIVE로 처리하고 공개 API로 수정 승인, 후보 생성, 규칙 초안 생성을 수행합니다. 규칙은 운영에 게시하지 않습니다. 실제 응답의 가공·모킹·지연 주입은 하지 않습니다.

검증: `node --test scripts/demo/contract.test.mjs`. 녹화 스크립트는 장면 실패 시 마지막까지 증거를 남기고 실패 종료합니다. 제품 콘솔 오류는 누락 없이 기록하되 영상 생성 완료와 구분하여 보고합니다. 제품 코드는 이 스크립트에서 수정하지 않습니다.

수정 전 재현: REC-2 계약 시험 2건이 기존 포트(9191/6491)와 13개 장면 때문에 실패했습니다. 첫 실제 실행에서는 데스크톱에서 숨겨진 새 요청 아이콘과 정책의 중복 accessible label을 선택하는 녹화 오류를 발견했고, 표시되는 대화 목록 버튼과 정책 fieldset으로 교체했습니다.

`node scripts/demo/verify.mjs artifacts/demo/<timestamp>`는 15개 장면 완료, 타임코드 순서, 실제 단계 표시 순서, PNG 크기, 취소·잠정 증거, H.264 영상 규격을 검증합니다. 초기 실패 실행에서 이 검증이 실패하는 것을 확인했습니다. 빠른 응답의 잠정 상태를 놓치지 않도록 전송 뒤 고정 지연 없이 다음 장면으로 진행하고, 재분석 확인 대화상자를 명시적으로 수락합니다.

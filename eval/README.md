# T24 평가 표본과 러너

`candidates/requests.jsonl`에는 제약사 업무 맥락을 반영한 가상 한국어 요청 120건이 있다. 환자·임직원 개인정보, 실명, 실제 회사명은 사용하지 않았다. 제안 라벨은 구현자가 만든 평가 후보일 뿐이며 모든 행의 `label_status`는 `proposed`다. 따라서 현업이 정답을 검토·확정하기 전 산출 지표는 `잠정(현업 미확정)`으로만 해석한다.

## 분할과 누출 방지

`candidates/tuning.jsonl`과 `candidates/final.jsonl`은 각각 60건이며 `manifest.json`에 각 파일 SHA-256과 표본별 정규화 JSON 해시를 고정했다. 최종 표본은 현업의 정답 확인과 최종 평가에만 쓰고 질문 문구·임계값 튜닝에 사용하지 않는다. 변경이 필요하면 새 표본 버전과 manifest를 만들어 검토 이력을 남긴다. 현재는 튜닝 실행만 허용하며 final split 실행은 최종 평가 승인 전 보류한다.

표본에는 일반 기술, AI 필요, 혼합, 정보 부족, 실행 전제 불충족, 조건부 가능, 현재 불가, 긴급·일반·판단 보류, 여러 담당 팀 조합이 순환 균형으로 포함된다. 임상·안전성, 약물감시, 규제 검토 후보가 15건 이상이고, 일부 입력은 Markdown 문서 형식 및 인용 데이터 안의 프롬프트 인젝션 문장을 포함한다. 이 후보 라벨과 근거는 현업 검토 전 정답으로 간주하지 않는다.

## 실행

저장소 루트에서 `backend/.venv/bin/python eval/runner.py --split tuning --max-samples 60 --concurrency 2 --retries 1`로 실행한다. 러너는 `JEV_MODE=live`와 기존 설정의 `JEV_API_KEY`를 확인하고 실제 `run_judgment`를 호출한다. `.env`를 수정하지 않으며 키, 요청 원문, 근거 발췌, SDK 예외 문자열을 터미널이나 결과 파일에 기록하지 않는다. 각 요청은 임베디드 judgment 호출 외에 최대 4개의 근거 확인과 업무 분해 호출도 수행하므로 60개 표본의 Jev 요청 비용은 최대 약 360회 호출 규모가 될 수 있다. 동시성은 기본 2이며 실패 시 행 ID와 예외 형식만 기록한다.

산출물은 `artifacts/validation/eval/<UTC timestamp>/raw.json`과 `metrics.json`이다. `raw.json`은 표본 ID·제안 라벨·예측·confidence·검토/자동 처리 신호·사용량·버전 및 안전한 실패 유형만 보존한다. `metrics.json`은 분류별 macro-F1, 긴급 recall, 클래스별 표본 수와 confusion matrix, 요청별 담당 팀 집합 F1 평균, confidence 구간별 정확도, 검토 전환율, 자동 처리 비율을 기록한다. 실패 표본은 정확도 계산에서 제외하고 실패 수를 별도 공개한다.

## 관찰 및 품질 개선 제안

SLO 목표는 최종 표본에서 AI 필요성·개발 가능성·긴급도 macro-F1 각각 0.85 이상, 긴급 recall 0.95 이상, 담당 팀 집합 평균 F1 0.85 이상이다. 2026-10-03 tuning live 60건 실행은 실패 0건이었지만 제안 라벨 기준 AI 필요성 macro-F1 0.253, 개발 가능성 0.554, 긴급도 0.919, 긴급 recall 0.857, 담당 팀 집합 평균 F1 0.217이었다. 모두 현업 미확정 표본으로 계산한 잠정 수치이며 목표 미달/미확정으로 보고한다.

혼동 행렬에서 AI 필요성 `불필요` 15건이 전부 `필요`로 예측됐고 `혼합` 15건 중 6건이 `정보 부족`으로 예측됐다. 다음 질문 문구 검토에서는 정해진 규칙·화면 자동화와 예측/분류가 필요한 업무를 구분하고, 기존 프로세스 개선과 모델 도입 필요성을 별도로 묻는 안을 제안한다. 개발 가능성은 `현재 불가` 16건 중 9건, `가능` 16건 중 7건이 `정보 부족`으로 예측됐으므로, 전제 확인 질문에서 자료 부재와 접근 불가, 승인 대기, 이미 확보된 조건을 각각 구별하도록 제안한다. 긴급 recall 0.857은 긴급 28건 중 4건을 일반으로 놓친 결과다. 기한과 지연 시 업무 영향에 관한 질문을 검토하고, 신호 신뢰도가 낮은 구간의 실제 일치율도 함께 확인한다. 검토 전환율 0.983, 자동 처리율 0.017, 낮은 confidence 구간의 정확도 0.138을 같이 본다. 담당 팀 집합 F1이 0.217이므로 업무 분해에서 초안 lead/collaboration team 조합을 명시적으로 평가할 필요가 있다. 이들은 tuning 결과에서 도출한 제안이며 현업 정답 확정과 별도 질문·임계값 검증이 필요하다. 무승인 배정·필수 검토를 완화하는 임계값 제안은 하지 않으며 judgment 코드는 변경하지 않았다.

개발 가능성·긴급도는 질문 정의를 tuning에서 두 차례 조정한 뒤 얻은 값이므로 최종 표본에서의 일반화는 보장되지 않는다(과적합 위험). 위험 질문은 별도 확인에서 위험 라벨 13건 모두 0.5 이상으로 표시했고, 비라벨 47건 중 20건이 명확(≤0.2)·20건이 0.5 이상·7건이 미확정이었다(보수적 방향의 과검출). 이 때문에 자동 처리율은 0이다.

남은 AI 필요성 오류: 필요→불필요 5, 혼합→불필요 3 등. 팀 F1 미달은 (1) 러너의 팀 집합 변환이 정적 카탈로그 lead를 합산하는 문제(러너 소유자가 판단 결과 `teams`를 쓰도록 변경 필요)와 (2) 아래 라벨 문제 때문이다.

라벨 의심 목록(변경 안 함, 현업 확인 필요):
- `team_set`: 동일 본문이 다른 team_set을 갖는 경우가 있고 본문에서 도출 불가(예: pharma-002 규칙 기반 화면에 AI팀 포함). 전반 재검토 필요.
- `ai_need=필요`인데 본문이 집계 화면·누락 표시 등 규칙/화면 성격: pharma-001, pharma-029, pharma-057.
- `feasibility=가능`인데 본문이 대상 데이터·기대 결과 미정: pharma-004, pharma-020, pharma-052 (qset-v2는 전제 기준으로 가능 판정).

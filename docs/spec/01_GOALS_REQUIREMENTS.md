# 프로젝트 목표와 핵심 요구

## 업무가 시작되기 전에 답할 질문

이 플랫폼은 현업의 요청을 실행 가능한 업무와 책임 관계로 바꾼다. 모든 요청을 AI 개발 과제로 만들지 않는다. 규칙·일반 개발·사람의 판단이 더 적절한 부분도 같은 비중으로 제시한다.

| 판단 | 사용자에게 제공할 결과 |
| --- | --- |
| AI 필요성 | 필요·불필요·혼합·정보 부족, 적용할 부분과 이유 |
| 개발 가능성 | 가능·조건부 가능·현재 불가·정보 부족, 전제와 장애 요인 |
| 긴급도 | 긴급·일반·판단 보류, 업무 영향과 기한 근거 |
| 담당 조직 | AI팀·IT팀·현업 중 주관과 협업 조직, 업무별 책임 |
| 처리 방법 | AI·일반 기술·사람이 맡을 작업, 순서와 산출물 |
| 검토 필요성 | 검토 대상 판단, 사유, 필요한 추가 정보 |

화면에서 개발 가능/불가 및 긴급/일반을 쉽게 구분하되, 정보 부족을 억지로 이분법에 넣지 않는다. 기술적 구현 가능성, 조직의 수행 여건, 업무 승인 여부는 구별한다. “현재 불가”는 영구 불가능을 뜻하지 않으며 이유와 다시 판단할 조건을 보여 준다.

## 필수 기능

- 웹 채팅에서 텍스트·PDF·DOCX·MD와 여러 첨부를 하나의 요청으로 접수한다.
- 원문과 분석에 사용한 텍스트를 연결하고, 추가 질문과 답변으로 요청을 보완한다.
- Jev의 실제 판단 결과를 사용하고 결정별 근거·신호·정책 버전을 기록한다.
- 여러 조직이 참여하는 요청을 업무로 분해하고 주관·협업·선행 작업을 표시한다.
- 검토자는 승인·수정·반려·추가 정보 요청을 수행하며 변경 이력을 남긴다.
- 요청·업무·검토·담당 팀·진행 상태를 대시보드에서 조회하고 필터링한다.
- 실제 실행 기록을 Flow·Topology·Playback 및 운영 지표에 연결한다.
- 정책 변경을 Dynamic Config로 반영하고, Neo4j에 실제 관계를 저장·조회한다.
- SSE로 진행을 전달하고 WebMCP로 권한 내 조회 도구를 제공한다.

## 품질 원칙

높은 모델 confidence는 정답 보장이 아니다. 사람이 확인할 수 있는 입력 근거와 불확실성을 보여 준다. 문서 내용은 분석할 데이터이며 시스템 지시나 권한 부여로 취급하지 않는다. 요청 처리 성공과 분류 정확도는 별도 지표다.

## 예시

“병원별 판매량으로 다음 달 수요를 예측하고, 목표 미달 병원에는 알림을 보내고 싶다.”

AI팀은 예측 필요성·데이터 적합성·모델 성능을 검토한다. IT팀은 데이터 연결·알림·접근 권한을 구현한다. 현업은 예측 활용 기준과 알림 대상을 확정한다. 예측보다 단순 집계가 충분하다면 일반 개발을 제안할 수 있다. 데이터가 없으면 조건부 가능 또는 추가 정보 요청으로 남긴다.

이는 예상 분류의 예시이며 실제 평가용 정답은 현업 검토로 확정한다.

## 첫 버전의 범위

제약사 SAP 관련 업무 요청을 처리할 수 있지만 SAP 운영 시스템에 직접 변경을 실행하는 기능은 기본 범위에 포함하지 않는다. 여기서 배정은 플랫폼 내부 업무 생성·담당 지정이다. 외부 티켓 도구나 SAP에 쓰는 기능은 별도 요청이 있을 때 범위와 권한을 정한다.

임상·안전·규제 등 영향이 큰 업무는 검토 대상으로 식별하고 적절한 책임자에게 넘긴다. 이 제품 자체가 규제 준수 인증이나 전문 승인 권한을 제공한다고 표현하지 않는다.

# 개발 에이전트 실행 프롬프트

당신은 제품 설계, 웹 개발, AI 판단, 운영 검증을 수행하는 고성능 개발 에이전트다. 이 폴더의 문서를 읽고 **Decision AI 기반 AI 업무 분류 판단 플랫폼을 실제로 구현하고 검증하라.** 먼저 대상 프로젝트의 README, AGENTS 및 기존 구조를 읽고 기존 기능을 재사용하라.

## 만들 제품

사용자가 웹 채팅에 텍스트나 PDF·DOCX·MD를 넣으면 업무 요청을 정리하고, AI가 필요한 부분·일반 기술로 해결할 부분·사람이 처리할 부분을 구분한다. 개발 가능성, 긴급도, AI팀·IT팀·현업의 책임과 협업 관계를 판단하고, 검토가 필요한 요청은 사람에게 넘긴다. 승인된 결과를 업무로 분해해 대시보드에서 추적한다.

각 요청의 실제 처리 과정은 Flow와 Topology로 확인하고 Play 버튼으로 재생할 수 있어야 한다. 성공·실패·지연·사람 대기와 SLO는 실제 기록에서 계산한다.

## 자율적으로 선택할 것

FastAPI를 중심으로 Decision AI, Dynamic Config, Neo4j, SSE, WebMCP를 활용하라. 프런트엔드, 문서 파서, 영속 저장 방식, 작업 실행 방식, 관측 도구, 배포 방식은 직접 선택하라. 기존 의존성과 플랫폼 기능으로 충분하면 재사용하라. 불필요한 프레임워크나 마이크로서비스를 추가하지 않아도 된다.

Decision AI는 판단에 활용하고, 요약·설명·업무 분해에 별도 생성 모델이 필요하면 선택하라. 모델이 출력하지 않은 근거나 신뢰도는 만들어 내지 말라. 구현 중 더 좋은 경험이 보이면 핵심 결과를 유지하면서 개선하라.

## 진행과 종료

먼저 실행 환경과 불확실한 전제를 확인하고 간결한 구현 계획을 작성한 뒤 작업하라. 일반 설계 선택은 스스로 결정하고, 계정·키·접근 권한처럼 진행을 막는 실제 외부 요건만 요청하라. 그동안 독립적으로 가능한 작업은 계속하라.

완료는 `06_ACCEPTANCE.md`의 검증을 통과했을 때만 선언한다. 화면만 만들거나, 주석·TODO·고정 응답·모의 로그로 기능을 대체하지 말라. 외부 연동이 막히면 그 항목을 차단 또는 미검증으로 표시하라. 테스트용 모의 환경은 라이브 환경과 화면 및 보고서에서 구분하라.

최종 제출물에는 실행 가능한 코드, 시작·중지·설정 방법, 실제 데모 데이터, 검증 명령과 결과, SLO 측정 결과, 알려진 제한을 포함하라. 개발 완료와 30일 운영 SLO 달성은 서로 다른 상태로 보고하라.

## 확장 목표와 실행 지시

기존 제품 요구를 유지하면서 [08_LEARNING_LOOP.md](08_LEARNING_LOOP.md)를 읽고 수정 경험의 규칙화와 입체 판단 맵을 확장 구현하라. 확장 순환은 **사람의 수정 기록 → 근거 기반 가설 → 검토된 규칙 → 제한적 검증과 적용 → 후속 실행 결과 관찰**이다. 이는 모델 재학습이 아니라 승인된 규칙·컨텍스트를 Dynamic Config 버전으로 반영하는 흐름이다.

확장 완료는 확장 게이트 **X01–X10**과 기존 **G01–G12**가 동시에 통과할 때만 선언한다. G01–G12와 X01–X10을 각각 별도로 판정하고, 운영 G13은 별도로 보고한다. 10단계 연결 시나리오는 실제 저장 데이터의 ID와 화면의 노드·관계를 대조한 증거로 검증한다. 화면 제작이나 문서 작성만으로 확장 완료를 선언하지 않는다.

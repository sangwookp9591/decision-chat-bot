# SLO 목표와 측정 기준

다음 수치는 **이 프로젝트의 초기 제품 목표**다. Decision AI나 특정 기술이 보장하는 성능을 인용한 값이 아니다. 개발 에이전트는 목표를 달성할 구조를 선택하고 실측으로 입증한다. 목표 조정이 필요하면 원인·비용·사용자 영향을 제시하고 제품 책임자의 승인을 기록한다.

## 기준 범위

초기 지원 입력은 요청당 텍스트 합계 20,000자, 첨부 5개, 파일당 10MiB·합계 25MiB 이내다. PDF는 파일당 50페이지 이내의 텍스트 추출 가능한 문서를 기본 성능 범위로 한다. DOCX·MD는 파일 제한 내에서 처리한다. 초과·암호화·손상·미지원 입력은 명확하게 거절하거나 정보 보완 상태로 전환한다. OCR을 추가하면 별도 성능 범위와 지표를 정의한다.

시간 기준은 클라이언트 업로드가 끝나고 서버가 입력을 받은 시점부터다. 파일 선택·업로드 네트워크 시간은 별도 관찰한다. 최초 판단 도착은 모든 필수 분류와 근거가 저장되어 자동 배정 가능 또는 사람 검토 가능 상태가 된 시점이다. 일부 토큰이나 빈 진행 이벤트는 완료로 세지 않는다.

## 지표와 목표

| 지표 | 분모와 계산 | 초기 목표 |
| --- | --- | --- |
| 접수·조회 가용성 | 권한·형식이 유효한 접수·조회 호출 중 정상 응답 비율 | 운영 30일 99.9% 이상 |
| 최초 판단 신뢰성 | 지원 범위 내 접수 요청 중 120초 내 최초 판단 저장 성공 비율 | 운영 30일 99.0% 이상 |
| 접수 응답 지연 | 입력 수신 후 요청 ID와 지속 가능한 상태 저장 응답까지, 실패 포함 | p95 2초 이하 |
| 텍스트 최초 판단 지연 | 입력 수신부터 최초 판단까지 | p95 15초 이하 |
| 첨부 최초 판단 지연 | 추출·정규화·판단·저장 포함 | p95 45초 이하 |
| 상태 반영 지연 | 상태 저장부터 연결된 브라우저 반영까지 | p95 2초 이하 |
| SSE 복구 | 네트워크 복원부터 최신 영속 상태 표시까지 | p95 5초 이하, 최종 상태 누락 0건 |
| 실행 추적 완전성 | 완료·실패 실행 중 필수 단계·분기·버전·종료 상태가 모두 기록된 비율 | 시험 100%, 운영 99.9% 이상 |

지연 표본에는 실패와 시간초과를 포함한다. 최초 판단에 도달하지 못한 요청은 120초 실패 표본으로 계산하고 실패율도 별도 표시한다. 취소는 취소 수로 따로 공개하며 이미 발생한 실패를 취소로 재분류하지 않는다. 유효 입력이 부하로 거절된 경우 가용성 또는 처리 실패 분모에서 제외하지 않는다. 외부 모델 장애 역시 최초 판단 실패에 포함한다.

사람 검토 대기는 최초 판단 이후 별도 시간으로 측정한다. 사람 검토 완료시간은 시스템 지연 목표에 포함하지 않지만 대시보드에서 p50·p95·최장 대기와 미처리 수를 표시한다. 반려는 정상 업무 결과이며 시스템 오류와 구별한다.

## 보완·재실행과 측정 단위

아래는 기존 목표 수치와 실패 기준을 유지하면서 정상 보완 흐름의 측정 단위를 명확히 한 규칙이다.

- **최초 요청:** 지원 범위의 최초 접수 수신 시각을 고정한다. 업무 정보가 부족해도 실제 판단으로 정보 부족/판단 보류, 원문 근거와 부족 정보, 검토 사유를 포함한 모든 필수 필드를 저장해 사람이 검토 가능한 상태로 만든다. 미정 담당/업무는 미정 사유와 함께 보존하며 가짜 값으로 채우지 않는다. 이 완전한 기록의 커밋 시각만 최초 판단 완료다. 추가 질문·빈 결과·상태 변경만으로 완료 처리하지 않는다.
- **보완 대기:** 위 판단 저장 이후의 사용자 답변 대기는 별도 지표다. 최초 판단 이전에 기다리게 됐더라도 기존 시계를 정지하지 않으며, 120초 내 완전한 기록이 없으면 최초 판단 실패와 120초 지연 표본을 유지한다. 정보 부족은 품질 평가에서 정답이 해당 클래스인 경우에만 정답이다.
- **보완·재분석:** 추가 입력은 새 input revision/run으로 기록한다. 수신부터 재판단 저장까지의 실행 지연을 별도 보고하고 최초 요청의 분모를 늘리지 않는다. 이전 요청의 시작 시각·성공/실패를 덮어쓰지 않는다.
- **재시도:** 최초 판단 전 재시도는 원래 수신 시각부터 누적한다. 원래 deadline 내 완전한 판단 저장이면 성공이고, 120초 이후의 회복 성공은 별도 회복 지표다. 이미 발생한 실패를 성공·취소로 재분류하지 않는다.
- **파일 부분 실패:** 손상·암호화·초과·미지원 입력은 객관적 제외 사유와 원본 접수 건수를 기록한다. 원래 부적격이던 요청이 사용자 제외/재첨부 후 처음 지원 범위가 되면 `(request_id, first_supported_revision)`을 첫 적격 표본으로 등록하고 그 확정 입력 수신 시각부터 측정한다. 최초 판단 집계에서 이 경로의 건수와 원본 제외 건수를 함께 공개한다. 이미 적격 표본이 있던 요청의 보완은 새 최초 표본을 만들거나 기존 실패를 덮지 못한다. 지원 파일의 파서 장애·모델/DB 오류·부하 거절은 미지원 입력으로 바꾸거나 분모에서 제외할 수 없다.
- **관측:** 접수·조회 호출 가용성은 각 유효 호출, 최초 판단 신뢰성은 요청당 첫 적격 표본 한 건, 재판단은 revision/run 단위로 각각 공개한다. Neo4j에 저장되지 않은 실패도 독립 journal의 attempt ID로 집계한다. 유효성 판정이나 수집이 누락된 표본은 미확정으로 공개하고 관측 불완전 구간의 통과를 주장하지 않는다.

예: 정보 부족 요청의 모든 필수 판단이 접수 후 8초에 저장되고 사용자가 1시간 뒤 답변하면 최초 판단 지연은 8초, 보완 대기는 별도다. 반대로 최초 판단이 120초 안에 저장되지 않았다면 다음 실행이 성공해도 원래 실패는 유지된다. 최초 입력에 스캔 파일이 있던 요청은 제외 이력과 첫 적격 revision을 함께 표시한다.

## 분류 품질과 안전 목표

현업이 정답과 허용 답변을 검토한 한국어 평가 요청 최소 100개를 준비한다. 각 핵심 분류에 정보 부족·혼합 업무·조건부 불가·긴급 사례를 포함한다. 질문·임계값을 조정하는 표본과 최종 평가 표본은 분리한다. 최종 평가는 최소 60개로 고정하고 임계값 조정에 재사용하지 않는다.

최종 표본에서 AI 필요성·개발 가능성·긴급도의 macro-F1 각각 0.85 이상, 긴급 사례 재현율 0.95 이상, 담당 팀 집합의 평균 F1 0.85 이상을 목표로 한다. 분류별 표본 수·오분류·검토 전환율·자동 처리 비율을 함께 보고한다. 판단 보류는 해당 정답 클래스가 아니면 오답으로 계산하여 모든 요청을 보류하는 방식으로 통과하지 못하게 한다. confidence의 높고 낮음별 실제 정확도도 확인한다.

승인이 필요한 요청의 무승인 배정, 권한 밖 조회·수정, 반복 승인으로 인한 중복 업무는 필수 안전 시험에서 0건이어야 한다. 이것이 모든 환경의 무결성을 보장한다는 의미는 아니다.

## 개발 완료 시험과 운영 SLO

개발 시험은 환경 사양·배포 버전·정책·모델·입력 크기를 기록하고, 30분 동안 동시 활성 요청 10개와 SSE 연결 20개를 유지하며 유효 요청을 최소 200건 처리한다. 텍스트 50%, PDF 25%, DOCX 15%, MD 10%로 구성하고 한도 근처의 입력도 포함한다. 예열 이후 측정하고 원시 시간 데이터와 분모를 보존한다.

이 시험에서 같은 지연 목표를 적용하며 가용성·판단 성공률은 각각 99.9%·99.0% 이상이어야 한다. 별도 장애 주입 시험은 정상 부하 시험과 분리하여 복구와 오류 노출을 검증한다. 운영 중 실제 장애 표본은 운영 집계에서 제외하지 않는다.

30분 시험 통과는 **개발 성능 게이트 통과**다. **운영 SLO 달성**은 실제 배포 후 연속 30일의 관측이 있어야 판정한다. 관측 기간이 짧거나 수집이 누락되면 미검증이다. 실패율 허용치는 각각 0.1%·1.0%이며 대시보드에서 남은 오류 예산과 소진 추세를 확인한다. 빠른 예산 소진·반복 장애·수집 중단의 알림을 실제로 발생시켜 확인하고 운영자가 원인 Trace를 찾을 수 있게 한다.

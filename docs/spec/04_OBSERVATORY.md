# 처리 흐름과 운영 관찰 화면

사용자가 “어디서 무엇을 했고, 왜 사람에게 넘어갔으며, 어디서 실패했는가”를 실제 기록으로 확인하는 화면을 만든다.

## Flow와 Topology

Flow는 선택한 요청의 실행 순서와 분기를 보여 준다. Topology는 요청·업무·팀·외부 서비스·의존 관계를 보여 준다. 업무 관계 그래프와 기술 실행 그래프를 함께 제공하더라도 의미가 구분되어야 한다. Neo4j의 저장 관계와 실행 기록을 사용하고 모든 요청을 같은 고정 그림으로 표현하지 않는다.

AI 판단, 일반 코드, 규칙, 외부 서비스, 사람이 수행한 노드를 이름·아이콘 등으로 구별한다. 노드 상태에는 대기·진행·성공·실패·건너뜀·검토 대기가 식별되어야 한다. 병렬 작업과 재시도는 실제 관계대로 표시한다.

## Trace 상세

노드를 클릭하면 실행 및 단계 식별자, 시작·종료 시각, 소요시간, 실행 주체, 입력·출력 요약, 원문 근거, 오류와 재시도, 정책·모델·스키마 버전을 확인한다. 판단 노드는 값·신뢰 신호·검토 전환 이유를 보여 준다. 사람 노드는 검토자·결정·수정·대기시간과 이력을 보여 준다.

모델의 숨겨진 사고 과정은 요구하지 않는다. 실제 반환값, 원문 근거, 정책과 사람의 결정으로 설명 가능해야 한다. 원문과 상세 데이터 접근은 권한을 따른다.

## Play 버튼

Play는 저장된 실행 기록을 시간 순서로 재생한다. 재생·일시정지·처음부터·속도 변경·구간 이동·전체 결과 보기를 지원한다. 긴 사람 대기는 압축할 수 있지만 실제 대기시간을 표시한다. 재생은 과거 기록 조회이며 모델을 재호출하거나 업무를 재배정하지 않는다. 재실행은 별도 동작으로 제공한다.

재생 중 활성 노드와 연결, 처리한 내용, 성공·실패·사람 전환을 강조한다. 실패한 실행은 실패 지점에서 실패로 끝나고, 건너뛴 단계가 성공 애니메이션으로 지나가지 않는다. 진행 중 요청은 실시간 모드와 과거 재생 모드를 구별한다.

## 성공과 실패 모니터링

요청 수, 자동 처리 수, 검토 대기·완료 수, 실패·시간초과 수, 처리시간 분포, 단계별 지연, 검토 대기시간, 재시도, 정책·모델 버전별 결과를 제공한다. 가능한 경우 실제 사용량과 비용도 표시하되 미수집 값은 0으로 표시하지 않는다.

외부 모델 장애, 파싱 실패, 저장 실패, SSE 연결 문제는 구별한다. 시간대·기간·조직·상태로 필터링하고 집계에서 원인 Trace로 이동한다. 빈 데이터·누락·수집 중단은 정상 수치와 구별한다. 지표의 집계 기간과 갱신 시각을 보여 준다.

## 입체 판단 맵

화면 09 **입체 판단 맵**은 실제 저장된 판단 관계를 다음 5계층으로 배치한다. 근거(`EvidenceSpan`, `ModelOutput`, `Correction`), 가설(`RuleCandidate`), 판단(`RuleDecision`, `ReviewDecision`), 적용(`RuleVersion`, `ValidationRun`), 업무 단계(`RunStep`)를 표시한다. 존재하지 않는 중간 관계를 만들지 않으며 관계가 없는 계층은 빈 상태로 보인다.

선택 경로를 강조하고 상세 패널에 계층·종류·출처·내용·결정 주체·시각·버전·상태·상류/하류 수를 표시한다. 권한 범위에서 원문 페이지·문단으로 이동하고 확대·축소·이동·전체 보기, 요청·규칙·버전·상태 필터를 제공한다. 관계가 많으면 경로 강조와 축약을 제공하며, 대체 목록 보기와 키보드 조작을 지원하고 reduced-motion 설정에서는 움직임 효과를 줄인다. 렌더링은 DOM 노드+CSS 3D+SVG 연결선을 권장하고 WebGL은 측정 근거가 있을 때 선택한다.

Flow는 실행 순서, Topology는 업무·시스템 관계, 판단 맵은 판단 근거와 적용 관계, 화면 10 **규칙 학습**은 후보·결정·검증·게시·효과의 규칙 수명을 나타낸다. 네 화면은 `request_id`, `run_id`, `step_id`, `review_id`, `candidate_id`, `rule_id@version`, `config_version` 식별자를 공유해 서로 이동한다.

## 규칙 효과 관찰

규칙 효과는 적용 전후와 규칙 사용/미사용 집단의 분류 변경, 사람 수정 비율, 검토 전환, 실패·지연을 보여 준다. 각 비교에는 비교 조건, 표본 수, 정답 표본 수를 함께 표시한다. 효과 판정은 `개선 확인`·`일부 확인`·`변화 없음`·`악화`·`관찰 중·표본 부족` 중 하나이며 표본이 부족하면 효과를 확정하지 않는다.

규칙 효과 지표는 SLO와 별도 지표다. 05_SLO의 수치와 분모 정의는 유지하며 섀도 실행은 SLO 분모에서 제외하고 별도로 공개한다.

## 관찰의 일관성

화면, 로그, 메트릭을 같은 요청과 실행으로 연결한다. 한 요청의 재시도가 요청 수를 부풀리거나 승인 대기를 실패로 계산하지 않도록 정의한다. 집계 숫자를 실제 실행 기록과 대조할 수 있어야 한다. 사람의 판단 수정은 원래 AI 판단을 지우지 않고 별도로 남긴다.

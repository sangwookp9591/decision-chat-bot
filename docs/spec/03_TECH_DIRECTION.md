# 기술 방향과 자율 설계 범위

기술을 나열하기 위해 사용하지 않는다. 아래 역할을 실제 사용자 흐름에 연결하고, 나머지 구조는 구현 에이전트가 정한다.

| 기술 | 필요한 역할 | 구현 선택의 여지 |
| --- | --- | --- |
| FastAPI | 접수·판단 실행·검토·조회·이벤트 API의 중심 | 모듈 구조, 작업 실행 방식, 배포 |
| Jev | AI 필요성·개발 가능성·긴급도·조직 등 판단 | 질문 구성, 호출 조합, 모델 버전 |
| Dynamic Config | 검토 임계값·라우팅·기능 정책 변경 | 저장 방식, 관리 UI, 적용 방식 |
| Neo4j | 요청·판단·팀·업무·의존 관계 저장과 조회 | 그래프 모델, 다른 저장소와의 역할 분담 |
| SSE | 진행과 상태 변경의 서버 발신 전달 | 이벤트 이름, 재연결·누락 보정 방식 |
| WebMCP | 웹 앱의 요청·업무·Trace 조회를 에이전트 도구로 제공 | 도구 목록, 지원 브라우저, 어댑터 |

## Jev의 경계

공식 문서상 Jev는 state와 typed questions를 받아 구조화된 판단을 반환한다. Choice와 Score에는 confidence가 있고 Noul은 참일 확률을 반환한다. 필드별 의미를 구분하며 없는 confidence를 합성하지 않는다. [TypeSafe 공식 문서](https://docs.typesafe.ai/introduction)

따라서 자연어 요약·근거 설명·업무 분해를 Jev가 모두 생성한다고 가정하지 않는다. 필요한 경우 다른 모델 또는 일반 코드가 맡는다. 설명은 원문 근거와 실제 판단 결과에 기반해야 하며 내부 사고 과정을 노출할 필요는 없다. 한국어·제약사 업무 정확도는 별도 검증한다.

API 주소·요청 형식·모델명·비용은 구현 시 공식 자료와 실제 응답으로 확인한다. 키는 서버에서 관리하고 브라우저·로그에 노출하지 않는다. 키가 없으면 모의 데모는 제공할 수 있지만 실연동 완료로 판정하지 않는다.

## 정책과 데이터

Dynamic Config는 변경 검증, 권한, 버전, 감사 이력, 되돌리기를 제공한다. 진행 중 실행은 시작 시 선택한 정책 버전으로 일관되게 처리한다. 예를 들어 검토 임계값을 바꾸면 새 실행에는 새 버전이 적용되고, 과거 판단을 새 정책으로 조용히 덮어쓰지 않는다.

Neo4j에는 실제 관계가 저장되어야 한다. 예를 들어 “요청 → 업무 → 담당팀”과 선행 업무를 조회해 Topology 또는 업무 상세에 표시한다. 거래성 데이터의 별도 저장소 필요 여부는 에이전트가 판단한다. 여러 저장소를 쓰면 일부 저장 실패와 재시도 후 정합성을 어떻게 복구하는지 검증한다.

SSE 연결이 끊겨도 영속 상태를 기준으로 복구한다. 이벤트 순서·중복·누락이 최종 업무 상태를 바꾸지 않아야 한다. 재시도 실행은 이전 실행과 구분하되 승인·배정의 부작용은 중복되지 않는다.

worker 인계는 단조 증가 소유권 generation과 만료 시각으로 보호한다. heartbeat와 모든 정식 결과 쓰기는 같은 트랜잭션에서 소유권을 잠금·검증한다. 과거 입력/실행은 최신 결과 포인터나 검토 대상을 덮지 못한다. 승인은 정확한 입력 revision·run·초안/검토 버전에 연결하며 배정·감사·이벤트와 원자적으로 커밋한다. 상세 계약과 경쟁 조건 시험은 [실행 계약 2절](../architecture/EXECUTION_CONTRACT.md#2-worker-소유권과-승인-대상)을 따른다.

업무 저장소 장애를 관측하기 위해 수신/종료·실패·소요시간의 journal과 수집 경로를 Neo4j와 분리한다. DB 저장 이전 실패도 attempt ID로 추적하고, 복구 후 커밋 기록과 대조한다. 수집 장애·미확정 분모·누락은 공개하고 정상 값으로 대체하지 않는다. 이 관측 기록은 업무 상태를 재실행하는 저장소가 아니다. [관측 계약](../architecture/EXECUTION_CONTRACT.md#3-neo4j-장애와-독립된-관측)을 따른다.

## WebMCP 호환성

2026년 10월 2일 확인한 공식 초안은 웹 앱의 JavaScript 도구를 에이전트에 노출하며 `Document`의 `modelContext`를 정의한다. W3C 표준은 아니므로 특정 API가 모든 브라우저에 있다고 가정하지 않는다. [WebMCP 공식 초안](https://webmachinelearning.github.io/webmcp/)

지원 환경에서 요청 검색·상세 조회·Trace 조회 도구를 실제 실행한다. 미지원 브라우저에서는 일반 화면과 API가 계속 동작한다. 서버 MCP 구현만으로 WebMCP 완료라고 부르지 않는다. 도구 실행에도 서버 권한 검사를 적용한다. 첫 버전의 쓰기 도구는 필수가 아니다.

호환성 사전 확인은 M0/T00에서 수행한다. 실제 브라우저·버전·필요 설정·도구 호출 환경과 최소 읽기 도구 실행을 확인한 뒤 T20의 제품 통합으로 진행한다. 지원 환경을 확보하지 못하면 해당 게이트를 차단으로 기록하고 독립 구현을 계속한다.

## 보안과 실패 처리

요청자·검토자·운영자의 권한을 분리하고 다른 사용자나 조직의 문서·요청·Trace가 노출되지 않게 한다. 파일 형식·크기·파싱 자원 제한을 실제로 적용하며, 문서 내부의 명령·스크립트·외부 참조를 임의 실행하지 않는다. 외부 모델로 보낼 데이터와 마스킹·보존 정책을 문서화한다.

민감 정보와 원문 전체를 기본 로그에 기록하지 않는다. 실패에는 사용자용 사유와 운영 진단 정보를 구분한다. Jev나 저장소 장애 시 성공으로 위장하거나 승인 없이 배정하지 않는다. 기술 선택은 자유지만 이 경계는 구현과 테스트로 보장한다.

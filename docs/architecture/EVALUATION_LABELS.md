# Evaluation label workflow

Frozen tuning and final samples are read from `eval/candidates/*.jsonl`; source candidate files remain unchanged. `labeler` and `reviewer` roles pass the `eval_label` action. Label decisions are append-only `EvalLabel` nodes, each paired with an `AuditEvent`, so independent reviewers can be compared without overwriting prior decisions. The API returns each reviewer's latest decision for a sample, so a new confirmed decision edits that reviewer's working answer while retaining its audit history. A deferred decision requires a reason; a later confirmation resumes that sample.

The evaluation API suppresses prediction and model output fields for final samples, including `proposed_labels`, model rationale, and scenario tags. Existing decisions by the current labeler remain available for editing. A sample with multiple distinct confirmed labels is marked `consensus_required`; an authorized labeler or reviewer can save an explicit consensus decision, recorded as `consensus_confirmed`. The candidate response includes confirmed, deferred, remaining, and percent counts for the current user, and exposes reviewer decisions and defer reasons for audit. The UI supports 1–4 field focus, Enter confirmation, and J/K navigation.

The export command writes only confirmed rows without unresolved disagreement to `eval/candidates/confirmed.jsonl`; explicitly resolved rows are marked `consensus_resolved`. It refreshes the artifact hash and count in the manifest. The runner prefers those confirmed labels and continues to report unconfirmed rows as provisional. Final samples remain segregated from tuning.

## Screen layout (UX-EVAL)

`frontend/src/pages/Evaluation.tsx` composes `pages/evaluation/*`: a header (split tabs 튜닝/최종 with a "모델 예측 숨김" badge on the final split, confirmed/deferred/remaining figures with a progress bar, previous/next stepper with `n / total`), then two columns that collapse to one below 960px. The left **표본** card shows the request text, proposed labels as chips (technical JSON folded in 기술 상세), the rationale, a consensus badge with the Korean sentence, and other labelers' decisions (name, decision, time, label chips, defer reason). The right **정답 입력** card has one `fieldset`/legend per field: ai_need, feasibility and urgency are radio chips (`role=radiogroup`, values exactly the domain `OPTIONS`; "정보 부족"/"판단 보류" sit in a separate dashed cell), team_set and risk_areas are `aria-pressed` toggle chips, then a 0–100% confidence slider with ticks, a defer reason textarea, and an action bar (확정 Enter, 보류, 합의 라벨 확정 when disagreeing, 이전 K, 다음 J) that sticks to the bottom on wide screens.

The API contract is unchanged: choices are saved as strings, teams and risks as arrays; no JSON text input remains. Confirming requires the three single-choice fields; deferring requires a reason (empty reason shows an inline error and focuses the field). Keyboard: 1–4 focus a field's chip group, arrows move inside a radio group, Enter confirms (not while typing in the textarea or on a focused action button), J/K move between samples. States: saving (controls disabled), success/error toast, empty sample list, skeleton after 200 ms, retry on load error, and a permission message on 403.

## 요약

G 게이트와 X 게이트는 분리되어 있고, 확장 요구 대부분은 08을 기준으로 00·01·02·03·04·06·README·PRD·TASK에 추적된다. 구현·시험 완료를 주장하는 문구도 발견하지 못했다. 상대 Markdown 파일 링크와 헤딩 앵커는 모두 존재한다.

## 지적 사항

### [심각도 중간] docs/spec/06_ACCEPTANCE.md:31 — X03 권한 게이트에서 범위 수정 승인이 빠짐

**문제:** 확장 기준 R21은 후보 범위 수정 후 승인도 규칙 관리자 권한으로 제한하지만, X03 통과 조건은 승인·기각·검증·게시·중단·되돌리기만 열거한다. TASK의 X03 증거 행도 범위 수정 권한 시험을 명시하지 않아 해당 동작의 권한 검증이 인수 기준에서 누락될 수 있다.

**근거:** 08의 R21은 `후보 승인·범위 수정 후 승인·기각(사유 필수)`를 요구한다(08_LEARNING_LOOP.md:39). 역할표에서도 후보 승인·범위 수정·기각의 권한은 규칙 관리자라고 정한다(08_LEARNING_LOOP.md:89). 반면 06의 X03 문구는 범위 수정 없이 권한 동작을 열거한다(06_ACCEPTANCE.md:31); TASK의 X03 증거도 `역할별 API 허용/403, 단건 승인 분리, 감사 기록`이다(TASK.md:180).

**제안 수정:** 06의 X03에 `범위 수정 승인`을 명시하고, TASK의 X03 증거에 권한 없는 범위 수정의 거절(예: 403), 권한자 승인 기록과 확정 범위 감사를 추가한다. 08의 X03 표기도 R21과 동일하게 정렬한다.

### [심각도 중간] TASK.md:147–148 — 규칙 상태가 08의 후보/결정 분리 모델과 불일치

**문제:** TASK는 `승인·기각`을 규칙 후보 상태에 포함하지만, 08은 후보 상태(제안/검토 필요/자료 부족)와 별도 `RuleDecision`(승인·범위 수정 승인·기각), `RuleVersion` 상태(검증/게시/중단/되돌림)를 분리한다. TASK는 또 08이 정의한 `검증 완료` 단계를 규칙 버전 상태 열거에서 생략한다. 구현 시 후보 상태와 결정·버전 수명 상태가 하나로 합쳐지거나, 게시 선행 조건 상태가 표현되지 않을 수 있다.

**근거:** TASK.md:147–148. 비교 기준은 08_LEARNING_LOOP.md:77–84 및 데이터 모델 08_LEARNING_LOOP.md:55–61이다. 08에서 후보·결정·버전은 별도 노드이며 검증 완료 뒤에만 게시된다.

**제안 수정:** 후보 상태를 `제안·검토 필요·자료 부족`으로 두고, 승인·범위 수정 승인·기각은 `RuleDecision`으로 분리한다. 규칙 버전 상태에는 최소 `검증 중·검증 완료·게시·중단·되돌림`을 반영하거나 검증 완료를 게시 가능 조건으로 명시한다.

### [심각도 낮음] docs/spec/06_ACCEPTANCE.md:42–51 — 10단계 연결 시나리오에서 X09 효과 관찰이 빠짐

**문제:** 06은 X09 효과 관찰 게이트를 별도 정의하지만, 연결 검증 시나리오 10단계에는 X09에 해당하는 적용 전후/사용·미사용 지표 관찰 단계가 없다. 08_LEARNING_LOOP.md의 같은 10단계 시나리오도 X09를 생략한다. 따라서 필수 연결 시나리오만 실행할 경우 규칙 적용 뒤 효과 관찰까지 이어지는 사용자 요구의 마지막 고리가 증거에서 빠질 수 있다.

**근거:** X09의 통과 조건은 06_ACCEPTANCE.md:37에 정의되어 있으나 시나리오는 06_ACCEPTANCE.md:42–51에서 X01–X08 다음 X10으로 이동한다. 기준 순환은 08_LEARNING_LOOP.md:11–20 및 효과 관찰 조건은 08_LEARNING_LOOP.md:95–101이다.

**제안 수정:** 10단계 이내에서 X09를 명시적으로 확인한다(예: 재시작·영속성 확인과 기존 회귀 확인을 한 단계로 묶고, 별도 단계에서 적용 전후 지표·표본 수·표본 부족 시 미확정 표시를 검증). 08과 06의 시나리오 및 TASK T38의 증거 기준을 함께 맞춘다.

## 점검 결과: 지적 없음

- `git diff HEAD`에서 기존 기능, 필수 검토·무승인 배정 금지, 기존 실행 버전 고정, 재분석·업무 변경 제한, 관측 분모 보존, SLO 목표 수치 또는 G01–G13 게이트의 삭제·약화는 발견하지 못했다.
- 05_SLO.md의 수치와 다른 신규 SLO 수치는 발견하지 못했다. 확장 효과 수치는 기존 SLO와 별도이며 표본 부족이면 미확정이라고 표현한다.
- 관찰 사실, 가설/후보, 승인 규칙 구분, 단건 수정 승인과 규칙 게시 승인 분리, 권한자 통제, Dynamic Config 버전·진행 중 실행 고정, 후속 실행 적용/미사용 기록, 재학습과 규칙·컨텍스트 반영 구분, 실제 저장 관계만 쓰는 5계층 맵, 상세·원문 이동·탐색·대체 목록 요구가 지정 문서에 대체로 반영되어 있다.
- 07의 이미지 관찰은 이미지에서 읽은 내용과 제품 사실 확인을 구분한다. 이는 시각적 관찰 기록이며 실제 제품 기능 증거라고 과장하지 않는다.
- 검사한 상대 Markdown 링크의 대상 파일과 헤딩 앵커는 모두 존재했다.
- 확장 설계가 구현·검증 완료를 암시하는 과장 표현은 발견하지 못했다.

## 불확실한 점

- 링크 앵커는 저장소 내 Markdown 헤딩의 GitHub식 slug 규칙으로 검사했다. 다른 렌더러의 특수 앵커 처리 차이는 별도 렌더링으로 확인하지 않았다.
- 요청에서 지정한 이미지 파일 원본은 이번 검토 범위에서 직접 열어 대조하지 않았다. 07의 이미지 관찰 내용이 실제 첨부와 일치하는지는 불확실하다. 07 자체는 그 관찰을 제품 사실로 취급하지 않는다고 명시한다.
